# Google Cloud Platform & Earth Engine Setup Guide

This document explains the steps to configure and activate the Google Earth Engine (GEE) adapter and Google Cloud Platform (GCP) infrastructure for the national and district-scale pipeline.

**Current Adapter Status**: Written, dry-run validated, ready-to-activate. Marked *untested against live EE* until authentication keys are provided. If keys are not configured, the system automatically falls back to Microsoft Planetary Computer with zero disruption.

---

## 1. Authentication Configuration Checklist

To activate Earth Engine, set the following environment variables in `.env`:

| Variable | Description | Requirement | Example |
| --- | --- | --- | --- |
| `GEE_SERVICE_ACCOUNT_KEY_FILE` | Absolute path to the GCP Service Account JSON key file | Recommended | `C:\Users\...\keys\gee-sa-key.json` |
| `GEE_SERVICE_ACCOUNT_EMAIL` | Service Account email address | Optional (parsed from key) | `ee-pipeline@my-project.iam.gserviceaccount.com` |
| `GEE_PROJECT_ID` | Google Cloud Project ID registered for Earth Engine | Required | `my-green-cover-project-2026` |
| `GCS_BUCKET_NAME` | Google Cloud Storage bucket for raster/COG exports | Optional | `india-green-cover-rasters` |
| `CARTO_API_KEY` | Optional key for keyed CARTO basemap | Optional | `your_carto_key` |

## 2. Step-by-Step Setup Instructions

### Step 1: Create or Select a GCP Project
1. Open the [Google Cloud Console](https://console.cloud.google.com/).
2. Create a new project (e.g., `green-cover-india`) or select an existing project.
3. Note your **Project ID**.

### Step 2: Enable the Earth Engine API
1. Navigate to **APIs & Services > Library**.
2. Search for **Earth Engine API** and click **Enable**.
3. Register your Cloud Project for Earth Engine access at [Earth Engine Cloud Signup](https://signup.earthengine.google.com/). Select your Cloud Project.

### Step 3: Create a Service Account and Generate JSON Key
1. In Cloud Console, go to **IAM & Admin > Service Accounts**.
2. Click **Create Service Account**:
   - Name: `ee-pipeline-agent`
   - Description: `Agent for automated satellite compositing and zonal statistics`
3. Grant Roles:
   - **Earth Engine Resource Viewer / Earth Engine User** (`roles/earthengine.user`)
   - If exporting to Google Cloud Storage: **Storage Object Admin** (`roles/storage.objectAdmin`)
4. Click into the newly created service account > **Keys** tab > **Add Key** > **Create new key** (select JSON).
5. Save the downloaded JSON key file securely (e.g., `C:\Users\yashw\.config\gcp\ee-key.json`).

### Step 4: Optional Storage & Hosting Setup
- **Google Cloud Storage (GCS)**:
  - Create a standard regional bucket in `asia-south1` (Mumbai) or `asia-south2` (Delhi) named e.g. `india-green-cover-rasters`.
  - Used for large multi-scene COG exports generated by Earth Engine tasks.
- **Firebase Hosting / Cloud Run**:
  - To host the static dashboard on GCP:
    ```bash
    npm install -g firebase-tools
    firebase login
    firebase init hosting
    npm run build
    firebase deploy
    ```

### Step 5: Update `.env`
Create or edit `.env` in the repository root:
```bash
GEE_SERVICE_ACCOUNT_KEY_FILE="C:/Users/yashw/secrets/ee-key.json"
GEE_PROJECT_ID="your-gcp-project-id"
GCS_BUCKET_NAME="india-green-cover-rasters"
```

## 3. Verification & Execution Commands

### Test 1: Validate GEE Configuration (Dry Run, No Live Auth Needed)
Test the pipeline query construction, band mapping, and date intervals:
```bash
python -c "from src.adapters.gee import GoogleEarthEngineAdapter; a = GoogleEarthEngineAdapter(); print(a.dry_run([68.0, 8.0, 97.0, 36.0], [2000, 2010, 2020, 2025], [4, 5]))"
```

### Test 2: Live Authentication Check
Once `.env` is populated, test live initialization:
```bash
python -c "from src.adapters.gee import GoogleEarthEngineAdapter; a = GoogleEarthEngineAdapter(); print('Initialized:', a.initialize_client())"
```

### Run National GEE Pipeline
To switch the pipeline to use Earth Engine:
In `config/config.yaml`:
```yaml
data_source: "gee"
```
Run the pipeline:
```bash
python execution/run_pipeline.py --config config/config.yaml
```
If credentials are valid, the pipeline will execute server-side compositing on Earth Engine servers and export results directly. If credentials are missing or expired, it prints a clear warning and falls back to Planetary Computer without aborting.
