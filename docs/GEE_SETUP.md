# Google Earth Engine Non-Commercial Activation Guide

This guide describes how to activate the non-commercial Google Earth Engine (GEE) adapter for this project. No credit card, Google Cloud billing, or service-account JSON key is required.

---

## 1. The 4 Commands to Run

Open your terminal in the repository root and execute:

```powershell
# 1. Activate the project environment (if not already activated)
.venv\Scripts\activate

# 2. Authenticate your non-commercial Google account with Earth Engine
#    (Opens a browser tab to log in with your registered Google account)
earthengine authenticate

# 3. Associate your registered Earth Engine Cloud Project ID
#    (Replace <your-ee-project-id> with your registered GCP project, e.g. primeval-melody-513507-t6)
earthengine set_project <your-ee-project-id>

# 4. Set the project ID in your local .env file
Add-Content -Path .env -Value "EE_PROJECT=<your-ee-project-id>"
```

*(Note: On bash / zsh, use `source .venv/bin/activate` and `echo "EE_PROJECT=<your-ee-project-id>" >> .env`)*

---

## 2. Verify Authentication with One Tiny Test Query

To verify that your credentials work without running a large job, run:

```powershell
.venv\Scripts\python execution/verify_gee_auth.py
```

Expected output:
```text
[GEE Auth] Successfully initialized Google Earth Engine with project: <your-project-id>
[GEE Auth] Querying 1 sample Landsat 9 scene over Bengaluru...
[GEE Auth] Verified: LANDSAT/LC09/C02/T1_L2 scene successfully retrieved!
[GEE Auth] ALL CHECKS PASSED. Ready for pipeline execution.
```

If credentials are not yet configured or invalid, it prints one clear message and exits immediately. It never hangs or blocks.

---

## 3. Dry-Run Mode (No Credentials Required)

To validate the GEE configuration, spectral band mappings, calibration equations, and query structures without any authentication:

```powershell
.venv\Scripts\python execution/run_national_gee.py --dry-run
```

This verifies:
- Landsat collection mapping (Landsat 5 TM for 2000/2010, Landsat 8 OLI for 2020, Landsat 9 OLI-2 for 2025)
- QA_PIXEL 16-bit cloud/shadow bitmasks
- USGS Surface Reflectance scaling (`0.0000275 * DN - 0.2`)
- Roy et al. (2016) OLI-to-ETM+ cross-sensor harmonization equations
- District zonal reduction chunking strategy

---

## 4. Run the National GEE Pipeline

Once authenticated, execute the national GEE pipeline with a single command:

```powershell
.venv\Scripts\python execution/run_national_gee.py
```

### Non-Commercial Quota Compliance
- **Zero Cloud Storage (GCS) Dependency**: Because non-commercial accounts do not require billing, outputs are computed server-side via `reduceRegions` and fetched in bounded batches directly to local files.
- **Drive Export (Optional)**: If full-resolution 30m GeoTIFFs are desired, use `--export-drive`.
- **Automatic Fallback**: If GEE credentials fail or expire, the pipeline prints a clear diagnostic and automatically falls back to Microsoft Planetary Computer.

## 5. Output Provenance

Every output generated by the GEE pipeline is tagged with a verified provenance manifest:
```json
{
  "_provenance": {
    "source": "google_earth_engine",
    "collections": [
      "LANDSAT/LT05/C02/T1_L2",
      "LANDSAT/LC08/C02/T1_L2",
      "LANDSAT/LC09/C02/T1_L2"
    ],
    "processing_pipeline": "execution/run_national_gee.py",
    "synthetic": false,
    "verified": true,
    "code_version": "v2.1"
  }
}
```
The dashboard automatically detects this manifest and displays `"Source: Google Earth Engine (Landsat 30m)"` in the tier badge.
